**วิธีรัน:** ใช้ผลทำนายเดิม (`runs/eval/yolo11n/preds_test.pkl`) และไฟล์ `per_code_test.csv` ไม่ได้เทรนหรือทำนายใหม่ ใช้ CPU อย่างเดียว ไม่ได้แก้ไฟล์ผลเดิม

## 1. จำนวนรหัสที่อ่านได้ไม่ตรงกัน

| วิธี | YOLO11n อ่านได้ / oracle ไม่ได้ | oracle อ่านได้ / YOLO11n ไม่ได้ | ผลต่างสุทธิ | exact McNemar p |
|---|---|---|---|---|
| ตัดตามกรอบ | 62 | 47 | +15 รหัส (+0.74 pp) | 0.18 |
| ผสม (ดัดภาพก่อน แล้วตัดกรอบสำรอง) | 18 | 14 | +4 รหัส (+0.20 pp) | 0.60 |

- **อ่านไม่ตรงกันในทั้งสองทิศ:** ไม่ได้มีแค่ YOLO11n ที่อ่านได้มากกว่า จำนวนสองฝั่งใกล้กัน
- **ผลต่างไม่มีนัยสำคัญทางสถิติ:** ทั้งสองวิธี (p = 0.18 และ 0.60)

## 2. ขนาดกรอบและขอบว่าง (quiet zone)

ใช้ค่ามัธยฐาน วัดเป็นจำนวน module และคิดขอบว่างจากด้านที่แคบที่สุดของกรอบเทียบกับมุมจริงของรหัส

| กลุ่ม | ความกว้าง mask: YOLO11n / oracle | ความกว้างกรอบ: YOLO11n / oracle | ขอบว่างด้านที่แคบสุด: YOLO11n / oracle | สัดส่วนที่ขอบว่างของ YOLO11n มากกว่า |
|---|---|---|---|---|
| ตัดกรอบ, YOLO11n อ่านได้ฝั่งเดียว (62) | 18.20 / 18.49 | 27.53 / 27.90 | 4.35 / 4.62 | 0% |
| ตัดกรอบ, oracle อ่านได้ฝั่งเดียว (47) | 18.31 / 18.67 | 27.65 / 28.04 | 4.39 / 4.63 | 0% |
| ผสม, YOLO11n อ่านได้ฝั่งเดียว (18) | 18.21 / 18.59 | 27.63 / 28.10 | 4.28 / 4.66 | 0% |
| ผสม, oracle อ่านได้ฝั่งเดียว (14) | 18.20 / 18.51 | 27.42 / 28.00 | 4.22 / 4.68 | 0% |

**สมมติฐาน "กรอบ YOLO11n กว้างกว่า จึงมีขอบว่างมากกว่า" ไม่จริง**
- กรอบของ YOLO11n **แคบกว่า** oracle ทุกรหัสในกลุ่มที่อ่านไม่ตรงกัน แคบกว่าประมาณ 0.2–0.5 module หรือราว 1–2 px
- oracle กว้างกว่าเพราะ mask ของ oracle วาดจาก 4 มุมจริงแล้วแปลงเป็นพิกเซล ได้กว้างประมาณ 18.5 module ส่วนรหัสจริงกว้าง 18 module
- ขอบว่างที่ต่างกันไม่ได้อธิบายผล เพราะทั้งรหัสที่ YOLO11n ชนะและรหัสที่ oracle ชนะ YOLO11n ก็มีขอบว่างน้อยกว่าเหมือนกัน

## 3. ppm, ความเอียง, ขอบภาพ

**ppm**
- **วิธีตัดกรอบ:** รหัสที่อ่านไม่ตรงกันกระจายทุกช่วง ppm (2–3: 10/3, 3–4: 14/10, 4–5: 12/12, 5–6: 13/9, 6–7: 5/6, 7–9: 8/7 สำหรับ YOLO11n ชนะ / oracle ชนะ) ค่ามัธยฐาน 4.6–4.7 ใกล้กับค่ามัธยฐานของทั้งชุด (4.68)
- **วิธีผสม:** รหัสที่อ่านไม่ตรงกันอยู่ที่ ppm ต่ำ ค่ามัธยฐาน 3.37 ไม่มีรหัสที่ ppm เกิน 6 เลย เป็นช่วงที่ตัวอ่านเกือบอ่านได้อยู่แล้ว
- **ในวิธีผสม ส่วนใหญ่ตัดสินกันที่ขั้นดัดภาพ ไม่ใช่ขั้นตัดกรอบ:**
  - YOLO11n ชนะ 18 รหัส: 14 รหัสอ่านได้เพราะดัดภาพจากมุมที่ YOLO11n ทำนาย ขณะที่ดัดภาพจากมุมจริงของ oracle อ่านไม่ได้
  - oracle ชนะ 14 รหัส: 12 รหัสอ่านได้จากการดัดภาพของ oracle

**ความเอียง**
- **ไม่เกี่ยว:** มัธยฐาน 1.6–1.9° ในกลุ่มที่อ่านไม่ตรงกัน ใกล้กับทั้งชุดที่มัธยฐาน 1.5° (P90 3.5°) และไม่ต่างกันระหว่างสองฝั่ง

**ขอบภาพ**
- **ไม่เกี่ยว:** ไม่มีรหัสใดในกลุ่มที่อ่านไม่ตรงกันอยู่ใกล้ขอบภาพไม่ถึง 3 module และมีเพียง 1 รหัส (อยู่ในกลุ่มที่ oracle อ่านได้ฝั่งเดียว) ที่ขอบภาพตัดกรอบของทั้งสองฝั่ง

## 4. เปลี่ยนขอบเผื่อของกรอบ

| ขอบเผื่อ | oracle ตัดกรอบ | YOLO11n ตัดกรอบ | oracle ผสม | YOLO11n ผสม | อ่านผิด (ทั้งสองฝั่ง) |
|---|---|---|---|---|---|
| 25% (ค่าที่ใช้ในผลหลัก) | 88.22% | 88.96% | 94.73% | 94.92% | 0 |
| 35% | 90.98% | 92.80% | 94.97% | 95.32% | 0 |
| 50% | 89.90% | 89.90% | 94.63% | 94.43% | 0 |

- **เพิ่มขอบเผื่อให้ oracle แล้วก็ยังไม่กลับมาสูงกว่า YOLO11n:**
  - ที่ 35% oracle ยังต่ำกว่า
  - ที่ 50% เท่ากันในวิธีตัดกรอบ และ oracle สูงกว่าเล็กน้อยในวิธีผสม
- **ผลขึ้นลงไม่เป็นทิศทาง:** ทั้งสองฝั่งสูงสุดที่ 35% แล้วลดลงที่ 50% แสดงว่าผลของวิธีตัดกรอบไวต่อขนาดกรอบเพียงไม่กี่พิกเซล ไม่ได้ขึ้นกับว่ามีขอบว่างมากหรือน้อย
- **ที่ไม่ควรสรุปจากตารางนี้:** ไม่ควรเปลี่ยนค่าในผลหลักเป็น 35% เพราะค่านี้ถูกเลือกโดยดูจากชุดทดสอบ ถ้าจะเปลี่ยนต้องเลือกจากชุด val

## 5. ภาพตัวอย่าง

`runs/oracle_crop_check/pair_1.png` ถึง `pair_5.png` เป็นรหัสที่ YOLO11n ตัดกรอบแล้วอ่านได้ แต่ oracle อ่านไม่ได้

- **ซ้าย:** กรอบของ YOLO11n
- **ขวา:** กรอบของ oracle
- **เส้นสีเขียว:** มุมจริงของรหัส

ภาพที่ดูแล้ว (pair_1, pair_3) สองกรอบต่างกันแค่ 1–3 px และรหัสในกรอบของ oracle ไม่ได้ดูแย่กว่า ทั้งสองคู่อยู่ที่ ppm ประมาณ 3.2–3.4 และมี noise มาก

## สาเหตุที่หลักฐานรองรับ

- **การอ่านของ zxing ที่ ppm ต่ำและภาพมี noise ไวต่อกรอบที่ต่างกันเพียง 1–2 px:** ตำแหน่งกรอบเปลี่ยนนิดเดียว ค่าที่ binarizer คำนวณก็เปลี่ยน ผลจึงพลิกได้ทั้งสองทาง
- **YOLO11n สูงกว่า oracle เพราะในรอบนี้ฝั่ง YOLO11n พลิกเป็นอ่านได้มากกว่าเล็กน้อย:** ผลต่าง 15 รหัสในวิธีตัดกรอบ และ 4 รหัสในวิธีผสม ไม่มีนัยสำคัญทางสถิติ
- **ไม่ใช่เพราะกรอบของ YOLO11n ดีกว่าอย่างเป็นระบบ**
- **ที่ยังไม่ได้ตรวจ:** ไม่ได้แยกดูว่าความไวนี้มาจาก binarizer ตัวไหนระหว่าง LocalAverage กับ GlobalHistogram

## สรุปภาษาไทยง่ายๆ

1. ที่ YOLO11n อ่านได้มากกว่า oracle นิดหน่อย ไม่ได้เป็นเพราะกรอบของ YOLO11n กว้างกว่า ตรวจแล้วกรอบของ YOLO11n แคบกว่าด้วยซ้ำ
2. รหัสที่ฝั่งหนึ่งอ่านได้แต่อีกฝั่งอ่านไม่ได้มีทั้งสองทาง คือ 62 กับ 47 รหัส และส่วนใหญ่เป็นรหัสที่เกือบอ่านได้อยู่แล้ว กรอบขยับแค่ 1–2 พิกเซลผลก็พลิกได้
3. ผลต่างนี้เล็กมาก (+0.7 และ +0.2 จุด) และไม่มีนัยสำคัญทางสถิติ จึงถือว่าทั้งสองฝั่งเท่ากัน
4. **ถ้าอาจารย์ถาม ให้ตอบว่า:** "oracle เป็นเพดานของวิธีดัดภาพ ส่วนวิธีตัดกรอบและวิธีผสม YOLO11n กับ oracle ไม่ต่างกันทางสถิติ ที่ YOLO11n สูงกว่า 0.2–0.7 จุด เกิดจากตัวอ่านไวต่อกรอบที่ต่างกันไม่กี่พิกเซล ไม่ใช่เพราะโมเดลหามุมได้ดีกว่ามุมจริง (ตัวเลขทั้งหมดจากภาพสังเคราะห์)"

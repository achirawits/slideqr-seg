# สรุปสถิติ (ภาพสังเคราะห์, แต่ละโมเดลเทรน 1 ครั้ง)

ตัวเลขเต็มอยู่ใน `docs/stats_synthetic.md` สร้างด้วย `scripts/per_code.py` และ `scripts/stats.py`
ทุกตัวเลขมาจากภาพสังเคราะห์ ยังไม่ได้ทดสอบกับภาพจริง

**วิธีที่ใช้ (ตาม RM07 "Statistical Testing with One Training Run")**
- **95% CI:** bootstrap 2,000 รอบ สุ่มเป็นภาพทั้งภาพ เพราะรหัสในภาพเดียวกันไม่เป็นอิสระต่อกัน
- **เทียบแบบจับคู่บนรหัสชุดเดียวกัน:** exact McNemar ปรับ p ด้วย Holm ในแต่ละตาราง α = 0.05
- **เทียบ 4 โมเดลพร้อมกัน:** Cochran's Q
- **ตรวจความถูกต้องของการส่งออก:** อัตราอ่านรวมที่ได้ตรงกับตารางเดิมทุกโมเดลทุกชุด

## RQ2: วิธีป้อนภาพ (rig)

| ช่วง | ผลต่าง วิธีผสม − ตัดกรอบ (pp) | มีนัยสำคัญหลังปรับ Holm |
|---|---|---|
| ทุกช่วงรวม | +4.0 ถึง +6.3 ทุกโมเดล | ใช่ ทุกโมเดล (p < 0.001) |
| 8MP | +7.2 ถึง +10.0 (Mask R-CNN, YOLO) | ใช่ ยกเว้น RF-DETR (ต่างกันแค่ 4–5 รหัส) |
| 12MP | +3.0 ถึง +4.2 | ไม่ (ต่างกันแค่ 5–7 รหัส จำนวนน้อยเกินจะยืนยันได้) |

- **สรุป:** ปฏิเสธ H0 ของ RQ2 ได้เมื่อดูทุกช่วงรวม และที่ช่วง 8MP แต่ที่ช่วง 12MP ยังสรุปไม่ได้
- **ข้อควรรู้ c = 0 ทุกแถว:** วิธีผสมลองดัดภาพก่อน แล้วค่อยตัดกรอบ เลยไม่มีรหัสไหนที่ตัดกรอบอ่านได้แต่วิธีผสมอ่านไม่ได้ ผลทางสถิติจึงวัดว่า "ขั้นสำรองเก็บรหัสเพิ่มได้จริงไหม" ไม่ใช่การแข่งกันของสองวิธีอิสระ
- **ภาพถือมือ:** วิธีผสมดีกว่าตัดกรอบแค่ +1 ถึง +2 pp เพราะมุมคลาดมากจนการดัดภาพแทบใช้ไม่ได้

## RQ1: โมเดล (วิธีผสม, rig)

| ช่วง | Cochran's Q | คู่ที่ต่างอย่างมีนัยสำคัญ |
|---|---|---|
| ทุกช่วงรวม | p < 0.001 | RF-DETR ต่ำกว่าอีก 3 โมเดล 1.4–2.2 pp, YOLO กับ Mask R-CNN ไม่ต่างกัน |
| 8MP | p < 0.001 | RF-DETR ต่ำกว่าอีก 3 โมเดล 6.7–7.7 pp |
| 12MP | p = 0.019 | ไม่มีคู่ไหนต่างหลังปรับ Holm |

- **สรุป:** ที่เวลาเทรนเท่ากัน YOLO11n, YOLO26n และ Mask R-CNN อ่านได้ไม่ต่างกันทางสถิติ RF-DETR ซึ่งได้แค่ 2 epoch ต่ำกว่าที่ช่วงความละเอียดต่ำ ส่วนที่ 12MP ทุกโมเดลไม่ต่างกัน
- **ผลต่อการตัดสินใจ:** เลือกโมเดลด้วยความเร็วและ license ได้ เพราะความแม่นในการอ่านไม่ต่างกัน YOLO11n เร็วกว่า Mask R-CNN ประมาณ 6.6 เท่าบน GPU (8 vs 53 ms)
- **ภาพถือมือ:** YOLO11n ต่ำกว่า YOLO26n และ RF-DETR 1.5–1.8 pp อย่างมีนัยสำคัญ ส่วนที่ช่วง 8MP และ 12MP ไม่มีคู่ไหนต่างกัน

## RQ3: 12MP เทียบ 8MP (วิธีผสม, คนละรหัส จึงไม่จับคู่)

ใช้ bootstrap สุ่มทั้งภาพแยกแต่ละช่วง และใช้ Fisher exact ประกอบ

| โมเดล | rig: 8MP → 12MP, ผลต่าง [95% CI] | handheld: 8MP → 12MP, ผลต่าง [95% CI] |
|---|---|---|
| Mask R-CNN | 96.7 → 97.0, +0.3 [−4.7, +5.2] | 81.6 → 90.6, +9.0 [+2.1, +16.3] |
| YOLO11n | 95.7 → 99.4, +3.7 [−0.0, +8.2] | 77.5 → 91.8, +14.3 [+7.2, +21.9] |
| YOLO26n | 95.7 → 99.4, +3.7 [−0.1, +7.9] | 78.3 → 91.8, +13.6 [+6.4, +20.9] |
| RF-DETR | 89.0 → 98.8, +9.8 [+3.5, +17.1] | 77.9 → 92.2, +14.3 [+7.4, +21.3] |
| oracle | 96.7 → 100, +3.3 [+0.0, +7.7] | 82.8 → 97.1, +14.4 [+8.6, +20.6] |

- **สรุป:** บนแท่นถ่ายภาพ กล้อง 8MP ก็พอสำหรับ YOLO และ Mask R-CNN ส่วนการถือกล้องด้วยมือ 12MP ดีกว่าชัดเจนทุกโมเดล

## ข้อจำกัดที่ต้องบอกตอนนำเสนอ
- **CI ครอบคลุมแค่ความแปรปรวนของชุดทดสอบ:** ไม่รวมความแปรปรวนจากการเทรน เพราะเทรน seed เดียว ถ้าจะเทรนหลาย seed ใช้ GPU ประมาณ 12 ชั่วโมงสำหรับ 3 seed × 4 โมเดล
- **ช่วงกล้องมีรหัสน้อย:** 209 และ 165 รหัส ผลต่างเล็กๆ จึงพิสูจน์ไม่ได้ ควรสร้างภาพทดสอบเพิ่มเฉพาะช่วง 3.5–5.0 px/module
- **ทดสอบหลายคู่:** ปรับ Holm แยกในแต่ละตาราง ไม่ได้ปรับรวมทุกตาราง
